# NPC 姓名资料

1.3.8 补入可核验的姓名，并未收齐所有 7.3.5 NPC。简体优先，繁体补缺；找不到可靠对应时保留原名。

| 查询方式 | 原有 | 现在 | 新增 |
| --- | ---: | ---: | ---: |
| NPC ID + 完整原名：有译文的 ID | 95,761 | 96,372 | 611 |
| NPC ID + 完整原名：名称对应数 | 95,767 | 96,392 | 625（简体 603、繁体 22） |
| 仅按完整原名查询：无歧义名称键 | 64,801 | 65,060 | 259（简体 242、繁体 17） |

多个 NPC ID 可能共用名字，一个 ID 也可能有不同的完整原名；两个索引存在重叠，数量不能相加。数据还包括隐藏、触发器、历史及内部记录，不等于玩家实际见到的 NPC 数量。

## 采用资料

- 已有 TDB 2018 世界库姓名及中文记录保持不变。
- 7.3.5.26972 Creature DB2 中英繁导出，原文件及 SHA-256 记录于 `sources.json.clientTables`。本地简体客户端导出与已有中文 CSV 内容一致；新接入的是此前没有用于这些姓名索引的配对，不将已有客户端覆盖重复算成新实体。
- [TrinityCore #21891](https://github.com/TrinityCore/TrinityCore/issues/21891) 的 2018 年 build 26365 同批中英繁客户端查询采集。固定 SQL、来源提交、语言、build 和 SHA-256 记录于 `sources.json.npcNameCaptures`。这是来源可追溯的社区采集，标记 `officialChineseVerified=false`，不等同于暴雪发布的数据库。

可验证例子：`Rhonormu` → `罗诺姆`、`Kanyr Skyhorn` → `坎雅‧天角`。同版 DB2 验证的 `Bigger Warsong Wolf` → `战歌恶狼` 别名也补入按原名索引。

## 匹配与保留规则

1. 配对资料必须同 ID、同名称字段；无英文别名时不借用主名做对应。有 ID 的显示入口继续同时核对原名指纹。
2. 新增对应先选简体、再选繁体；同语言的同 ID/原名优先采用 DB2。相同优先级的异译暂缓，同名不同 NPC 的译文不能凭来源优先级互相覆盖。
3. 既有译文保留。新增全局原名键须检查其他 ID 的名字与别名，既有歧义键不恢复。71 项与旧译不同的候选保留旧译并记录；其中 3 项是 ID 标签、68 项是全局原名。另记录 14 个与既有全局键有关的跨 ID 异译，不将保留的旧键声称为新解决的歧义。
4. 这批候选中的 56 个原名键因旧歧义继续不用于仅按名字查询；相应 ID 的明确配对仍可使用。最终全局排除键为 171 个，审计记录可能多次指向同一键，不能把日志条数当作缺译数。
5. 玩家名、自定义宠物名和无可靠对应的随机名不猜译。`Casketmasher` 没有因本次扩充获得可靠对应，仍保留原名。

## 已知缺口

在当前可审计基础库的非空外文主名／别名范围内，仍有 **10,656 组 ID+原名（涉及 10,648 个 ID）**没有对应标签译文。该范围不是所有 7.3.5 NPC 的总表，不包括每个服务器的自定义数据，也不代表这些 ID 的所有名称都缺失。

姓名库不包含完整 NPC 对白和头衔翻译；本次没有增加这两类资料。客户端 Creature 主名数据本身有 661 个 ID 没有可用中文主名，且安装目录的姓名缓存为空，不能仅靠下载客户端补齐所有服务器姓名。

构建逐项核对、选择结果、旧译冲突和缺译清单见 [npc-name-audit.json](npc-name-audit.json)。源码资源只含中文与数字 ID／原名指纹，原始英文仅在开发审计中保留。沿用单个插件内的按需初始化，不新增运行时全库扫描。

## 游戏内核验

更新后核对原版 NPC 头像框、鼠标提示及可访问姓名板；有收录原名时应显示中文，自定义或不匹配原名保持不变。任务列表或追踪栏中的 `Return to Rhonormu.` 等完整简短提示可复用新姓名；额外地点和未知姓名仍保留原文。

自动测试会验证实际生成的名称与运行入口、未知姓名保护、旧译不覆盖、简繁回退及来源校验；这不代表已完成实际服务器的显示、字形和兼容性验收。
