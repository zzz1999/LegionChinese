# 1.3.5 运行时性能检查

本轮在保持译文选择和原文保护规则的前提下整理模块，并减少能够复现的重复工作。测试包含先前已加入的任务变量数据；性能比较的基线是本轮重构开始时的工作区，不是较早的 1.2.11。

## 本轮变化

- **文本规范化**：缓存最多 128 条不超过 2,048 字节的静态输入，复用规范化结果及原函数的第二返回值。输入字符串上限为 256 KiB，另有输出字符串、键表和 Lua 对象开销。动态角色替换不缓存；长文本不入缓存。
- **角色别名**：每次读取玩家姓名、职业、种族，与上次身份比较；身份和本地化名称不变时复用别名表，变化时重新建立，避免使用旧角色名字判断中文或匹配变量。
- **聊天历史索引**：为待加载链接记录相对插入位置和历史容器代次。资料到达后先核对当前位置的条目身份，只处理对应消息；遇到其他插件删除、替换或调整记录时退回原生遍历并修复索引。移出历史的消息不会被修改。索引保留原有弱引用，不阻止旧消息回收。
- **场景物件提示**：原生显示和清除事件仍即时处理；无事件的引擎更新以约 0.1 秒间隔补查，不追赶卡顿期间错过的帧。提示框被替换后首轮即时检查，不改变原生 OnUpdate。
- **已有优化保留**：指纹最多缓存 128 条、每条 512 字节；物品提示正文的兜底轮询约每 0.1 秒一次。关于窗口按需创建并复用。

## 可重复的模拟基准

```powershell
npm run benchmark
# 可选：使用本轮修改前保存的运行时文件
node scripts/benchmark-runtime.mjs .cache/refactor-runtime-baseline
```

脚本使用 Fengari 和项目的 7.3.5 界面测试桩。基准加载器已同步拆分后的依赖，并为旧版聊天模块补齐 Hooks 依赖。

| 同一场景中的操作次数 | 本轮修改前 | 本轮修改后 |
| --- | ---: | ---: |
| 相同文本规范化 2,000 次：string.gsub 调用 | 22,000 | 11 |
| 1,000 行聊天、200 个未缓存链接，其中 1 个资料到达：遍历历史条目 | 1,000 | 0 |
| 上述场景：物品信息查询 | 1 | 1 |
| 场景物件提示一秒 120 帧：上下文检查 | 120 | 10 |
| 30 行物品提示一秒 120 帧：正文 GetText | 290 | 290 |
| 相同 192 字节输入计算指纹 2,000 次：处理字节数 | 192 | 192 |

历史位置核对仍会读取对应条目，所以“遍历 0 行”不表示没有任何操作。历史被其他插件改变时允许退回遍历，以正确性优先。以上数据不是游戏内 CPU 时间、内存占用或 FPS。

## 数据按需加载

发布包只有一个 `LegionChinese` 插件。内部按任务、专业／副业、对白等 14 类登记初始化函数；首次查询某类资料才创建该类的数据表和匹配索引。NPC 姓名索引单独初始化，任务交付提示查姓名时不会连带初始化对白。共用中文词条按 ID 范围分成 25 片，只创建实际读取的分片，采用二分查找定位，已经加载的值直接查表。

包检查确认转换前后 41 组、2,273,043 条资源赋值等价。针对发布格式的模拟测试确认：启动未创建任务／专业／对白等大型表；首次任务查询只初始化任务分类，首次专业查询只初始化专业分类；重复查询复用原表，已中文内容不会触发这些查询。

单插件的 Lua 文件仍在启动时读取、编译；函数及字符串常量仍有启动成本，延后的是表的创建。不能将资源文本字节数当成内存节省量，也不能据此承诺更快登录。初始化成功后释放函数引用，已创建的资料保留到退出或重载界面。真实界面一旦查询某分类就会初始化它，包括任务追踪栏或聊天事件自动触发的查询；不要求必须手动打开窗口。

## 回归与实机边界

回归覆盖缓存淘汰、长输入、身份变化、完整载荷、未缓存链接、历史裁剪和替换、提示框复用与节流、按需首次加载、中文不触发普通查询加载、简繁回退、未完成登记、初始化失败与重入、失败后清理与重试，以及共享池释放后的初始化。

GitHub Actions 的检查任务同时运行单插件资源转换等价校验，之后才打包和发布。完整模拟通过不代表实机验收完成；下一步优先按 [客户端验收](CLIENT-CHECK.md) 比较同一环境中的登录、首次 NPC 对话／要塞界面耗时和插件内存，评估首次初始化的实际成本。
