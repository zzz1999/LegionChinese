# 1.2.11 运行时性能检查

检查范围包括任务和追踪栏、聊天链接、NPC/书籍匹配、读条、宠物名称、物件与物品提示框、关于窗口。此次优化集中在可以复现的重复工作，保留现有词库及译文选择规则。

## 本轮修改

- **聊天资料重试**：物品、钥石或冒险指南资料到达后，只重新处理正在等待该资料的消息；同一批次在多个窗口间复用完整链接的查询结果。仍遍历原生历史容器检查条目，避免修改已删除的消息，但不再解析和查询无关行。普通无链接聊天直接跳过解析。
- **物品提示框**：显示、物品载入、原生 setter 和 `/lcn` 开关仍即时处理。仅兜底轮询改为约每 0.1 秒一次；关闭汉化时不轮询。低帧率或卡顿时不追赶执行多轮扫描，不干预原生 `OnUpdate`。
- **匹配指纹**：最多保留 128 个输入，每个输入不超过 512 字节，缓存键文本的上限为 64 KiB，另有哈希值与表的开销。长书页不进入缓存。只缓存与角色无关的指纹，译文与玩家姓名、种族、职业替换仍重新判断。
- **重试正确性**：查询暂时返回外文名称时，同一链接的每条消息都继续等待后续中文资料；不会因为本批次复用查询结果而丢失等待状态。

本次没有更改物件提示框的逐帧首行检查、数据加载结构或词库体积。读条、任务和宠物名称的现有事件路径保持不变。关于窗口按需创建并复用，没有持续轮询。

## 可重复的模拟基准

运行：

```powershell
node scripts/benchmark-runtime.mjs
```

脚本使用 Fengari 和项目的 7.3.5 界面测试桩，统计实际进入 API/字符串处理的次数。下表的“优化前”来自本轮开始时的 1.2.11 工作区，已包含物品说明和“学海无涯”数据补充。

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 1,000 行聊天、200 个不同的未加载物品，其中 1 个资料到达：物品查询次数 | 200 | 1 |
| 30 行提示框，一秒 120 次原生刷新：正文 `GetText` 次数 | 3,480 | 290 |
| 相同 192 字节文本计算指纹 2,000 次：哈希处理字节数 | 384,000 | 192 |

保留旧版 `Core.lua`、`ChatLinks.lua`、`ItemTooltips.lua` 的目录可作为可选参数，用同一套场景运行修改前代码：

```powershell
node scripts/benchmark-runtime.mjs .cache/runtime-before-performance
```

这些数字不是游戏内 CPU 时间、内存占用或 FPS。没有实际 7.3.5 客户端性能采样，不能据此承诺帧数提升百分比或登录加载时间变化。实机步骤见 [CLIENT-CHECK.md](CLIENT-CHECK.md)。

## 回归验证

测试覆盖异步资料重试、多个窗口、完整物品后缀、已移除消息、外文缓存结果、开关汉化、未知物品、提示框复用、延迟追加文字，以及指纹缓存的容量限制与淘汰。已有任务、NPC、书籍、读条、字体和发布测试继续运行。

聊天容器行为核对了原版 7.3.5 的 [ScrollingMessageFrame.lua](https://github.com/Gethe/wow-ui-source/blob/67ecbf5ce0e50cc7483c2295caecf410460f0994/SharedXML/ScrollingMessageFrame.lua) 和 [CircularBuffer.lua](https://github.com/Gethe/wow-ui-source/blob/67ecbf5ce0e50cc7483c2295caecf410460f0994/SharedXML/CircularBuffer.lua)。不替换聊天容器、不清空重放消息，也不依赖其私有索引布局。
