# 代码与资源结构

1.3.5 在既有分目录资源上整理运行时职责，并在单个插件内按功能延后数据表初始化。重构不改变匹配键、关联 ID、简体优先或繁体补缺规则；本版另有独立核验的任务变量补充，见更新记录。

## 运行时

| 文件 | 职责 |
| --- | --- |
| `Bootstrap.lua` | 建立资源表和插件命名空间 |
| `DataAccess.lua` | 资源查询入口、分类初始化、中文词条分片查询和失败重试 |
| `Text.lua` | 原文规范化、指纹、玩家别名、变量渲染和有界文本缓存 |
| `Core.lua` | 任务原文校验、按类别查询、动态匹配与译文选择 |
| `WidgetText.lua` | 原生字体选择与翻译结果写入 |
| `Hyperlinks.lua` | 链接载荷解析、可靠名称查询和链接显示文字替换，不操作聊天窗口 |
| `QuestTemplates.lua` | 按任务 ID、字段和完整原文绑定经核验的任务变量；保留服务器实际需求数量 |
| `Hooks.lua` | 按功能与槽位注册挂钩；一个原生挂钩分发多个功能回调，同功能重新注册只更新回调 |
| `Bindings.lua` | 共用文本写入、递归保护、颜色保留及分范围资料绑定 |
| `Modules/Quests.lua`、`QuestTracker.lua`、`CastBars.lua`、`Books.lua` | 任务窗口与对话入口、追踪目标、读条、书页各自的显示逻辑与状态 |
| 其他 `Modules/` | 地图标签、坐骑、玩具、幻化、专业、考古、声望、要塞任务、追随者、建筑、研究、地下城排队、场景和成就条件 |
| `ChatLinks.lua` | 聊天窗口挂钩、待加载链接索引、历史记录更新及资料到达事件 |
| 其他功能 Lua | 任务板、神器、物品与其他提示框、聊天链接、对白显示等原有功能 |
| `Changelog.lua`、`Welcome.lua` | 游戏内更新记录和介绍窗口 |
| `UI.lua` | 按具名功能登记表安装挂钩、处理插件生命周期事件和注册 `/lcn` 命令 |

移除混合多个界面职责的 `LocalClient.lua`，将其数据查找改名为 `FindCatalog`。这只是内部组织调整。`UI.lua` 在登录、相关暴雪界面加载或相关框体／全局处理函数出现与更换时补装挂钩；无关插件加载且目标未变化时跳过安装器。检查只读取已列明的目标引用，不扫描全部框体。

1.3.2 的 `Toys`、`Wardrobe`、`Archaeology`、`Research`、`Followers` 和 `Buildings` 模块复用既有分范围资料。动态控件在固定容器或原生池中登记，字段写入在原版排版前处理；首次创建的技能提示再按文本高度差修正父框体。共享下拉菜单和鼠标提示只在已识别的原版调用中直接替换，不给这些共享文字挂无条件替换回调。所有新入口均不添加 `OnUpdate` 扫描。

## 资源目录和加载清单

`scripts/resource-layout.mjs` 是目录、资源家族和加载顺序的唯一登记处，同时生成 TOC 与 `docs/resource-manifest.json`。

| `Data/` 子目录 | 内容 |
| --- | --- |
| `Shared` | 共享中文、基础中文串、名称串和分范围中文串 |
| `Quests` | 任务、原文保护索引、标题、目标、完成提示、补充对白和任务板 |
| `Dialogue`、`Books` | NPC 对话、书页及上下文 |
| `Items`、`Spells`、`Creatures` | 物品、法术、光环、NPC 及宠物名称 |
| `Maps` | 世界物件、地下城、地图地点和排队说明 |
| `Collections`、`Professions`、`Reputation`、`Garrison` | 收藏、专业、声望和要塞的分范围指纹 |
| `System`、`Artifacts` | 其他客户端说明、链接名称、系统固定文字和神器资料 |

加载顺序为：初始化 → 共享中文和其他资源 → 核心与共用工具 → 各功能模块 → 更新记录和介绍窗口 → 界面入口。仍按大小分片，默认每片赋值正文上限 900,000 字节，不合并成巨大单文件。单条赋值超过上限会使构建失败。

### 发布包的按需加载

源码目录保留一份完整资料，其 TOC 仍直接加载，便于生成器和原有数据审计工作。发布脚本 `scripts/package-layout.mjs` 在临时目录内将数据赋值包成初始化函数；最终只有一个 `LegionChinese` 文件夹和 TOC，不创建其他数据插件。发布加载顺序是 Bootstrap → DataAccess → DataManifest → 数据初始化函数登记 → 其余运行时。

`DataManifest.lua` 从资源赋值目标生成 14 个功能分类及各分类的文件数。任务、专业／副业、对白、物品等分别管理。`NPCNames` 源文件仍归入 `Data/Dialogue`，发布包中独立登记为 `NPCNames` 分类，避免任务交付提示查姓名时初始化整组对白。首次访问分类表或分范围索引时，通过表的 `__index` 初始化该分类；后续直接读取已经创建的表。兼容现有 `D.Quests[id]` 等 ID 查询和 `A.Data.Get/Catalog` 查询，无需改动译文优先级与索引键。未完整登记的分类不会初始化；异常时移除整个分类的半成品表，并最多每 5 秒重试，保留原文。生成器中的赋值无外部回调，初始化前先建立同分类的空目标表，避免依赖自身时重入。

`Strings`、`NameStrings`、`CatalogStrings` 的 25 个中文词条分片按 ID 范围建立小索引；首次读取某个 ID 时二分定位并只初始化相应分片，已加载值直接读表。临时去重用的 `SharedStrings` 在打包时还原为常量并从发布清单移除，避免延迟函数依赖启动后已释放的共享表。初始化成功后释放对应函数引用。

单插件的资源文件仍会在启动时被客户端读取和编译，字符串常量与函数也占内存；延后的是大型数据表和索引的创建，不能称为延迟文件读取。初始化后不自动卸载，首次使用可能有停顿，实际收益需实机比较。源码 TOC 是直接加载形式，必须使用发布 ZIP 验收此行为。

`npm run check:package` 核对单一插件目录、实际 TOC、Lua 5.1 语法和版本，对转换前后所有资源赋值做语义核对。本轮 41 组、2,273,043 条赋值完全一致。测试还验证任务与专业首次使用互不创建数据、中文跳过查询、词条分片按需创建及失败恢复。

`QuestTemplates` 是单独审核的任务变量资源。`scripts/quest-variables.mjs` 只为固定快照编译 `$p`、`$r` 和 `$1oa` 至 `$32oa`，不放宽其他数据的变量拒绝规则。外文片段只保存字节长度和双指纹，中文保存已编译的数字槽位；安装包不包含外文正文。运行时直接索引一个任务字段，顺序比对完整原文，不扫描全库，不添加轮询。玩家值按当次 API 结果读取；数量只接受规范的非负十进制整数，重复变量必须一致。未知或不匹配的内容回退原文。

清单记录每片的家族、目录、大小和 SHA-256，以及运行时文件依赖。检查程序拒绝未知资源家族、错目录、重复条目、丢失文件、错误顺序、过期清单和悬空共享引用。新资源家族须先登记；不要手工调整 TOC 或生成资源。

## 共享中文

保留原有 `Strings`、`NameStrings`、指纹索引和数字 ID，仅将重复且能抵消声明／引用成本的中文常量放入临时 `SharedStrings` 池。资源加载时直接取得普通字符串；进入 `Core.lua` 后释放池表，运行中的匹配不经过额外共享表查找。

1.3.1 的构建结果为 22,185 段共享中文、131,372 处引用，生成的 Lua 文本减少 2,728,718 字节（约 2.6 MiB）。这是打包前资源文本的差额，不代表 ZIP 减少相同体积，也不是帧率或游戏内存实测。

## 构建与恢复

```powershell
npm ci --ignore-scripts
npm run build
npm test
npm run check
npm run check:package
npm run benchmark
./scripts/package.ps1
```

构建默认从 `.cache` 读取已经下载并固定哈希的资料；也可以运行 `npm run build -- <资料目录>`。缺少资料或校验不通过时停止，不修改当前安装资源。

生成器的过程为：

1. 独占 `.cache/build.lock`，在同一仓库的 `.cache/build-stage-*` 中复制输入和运行时文件。
2. 生成资源、选择有收益的共享常量、按功能归档，生成 TOC、清单及审计报告。
3. 检查 Lua 5.1、中文资料、变量、共享引用、版本、更新记录、图标、资源哈希与加载顺序。
4. 再次核对配置、运行时代码、生成器和资料快照的输入哈希；期间有改动就拒绝替换。
5. 备份旧插件及被替换的 JSON 报告，再移动已校验的候选；出错时恢复旧文件。
6. 清理临时目录和构建锁。如果文件系统错误阻止回滚，保留临时目录中的备份并报告路径，仍释放锁。

该流程覆盖进程内可捕获的生成、校验与替换失败。突然断电或强制终止进程不保证自动回滚；遇到遗留锁时，应先确认没有构建进程，再检查临时目录和备份，不能直接清空整个 `.cache`。构建和打包均不自动安装到游戏目录，也不自动发布。

手写 Lua 使用 `.stylua.toml`：Lua 5.1、四空格、110 列，展开控制流。格式化范围为 `Bootstrap.lua` 与 `resource-layout.mjs` 的运行时文件，排除自动生成的 `Changelog.lua`；不要格式化 `Data/` 资源。可用 StyLua 2.6.0 的 `--verify` 检查格式化前后语法树，提交前再运行完整回归测试。数据生成器继续使用紧凑资源格式，避免格式整理增加加载体积。

## 等价核对与测试边界

本次修改前保存了 1.3.0 的资源赋值基线，随后运行：

```powershell
npm run build -- --verify-equivalence docs/refactor-baseline-1.3.0.json
```

`resource-equivalence.mjs` 展开共享引用、对应内部目录改名，按资源表核对赋值数量和 SHA-256 汇总；目录、分片边界和相互独立的赋值顺序不作为差异。本次 40 组、2,273,007 条赋值一致，结果见 [refactor-equivalence.json](refactor-equivalence.json)，原始基线见 [refactor-baseline-1.3.0.json](refactor-baseline-1.3.0.json)。这用于验证本次资源搬迁，不应要求未来新增译文仍与旧版本相等。

测试另覆盖原版框体迟加载、无关插件事件、多个功能共用挂钩、异常后的递归保护、真实共享资源执行、构建锁和替换回滚。原有针对少量数据的测试通过 `tests/addon-fixture.mjs` 读取新目录并展开共享值；共享引用和生产加载顺序由独立集成测试验证。

自动检查不代替游戏中的排版、加载时间、内存、战斗保护与其他插件兼容性验收。1.3.1 的复测步骤见 [CLIENT-CHECK.md](CLIENT-CHECK.md)。
