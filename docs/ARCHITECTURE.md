# 1.3.1 代码与资源结构

本版整理模块、资源目录和生成流程。汉化资料、匹配键、关联 ID 及简体优先、繁体补缺规则与 1.3.0 保持一致，不计为新增汉化内容。

## 运行时

| 文件 | 职责 |
| --- | --- |
| `Bootstrap.lua` | 建立资源表和插件命名空间 |
| `Core.lua` | 原文规范化、指纹、匹配、变量渲染及原生字体处理 |
| `Hooks.lua` | 按功能与槽位注册挂钩；一个原生挂钩分发多个功能回调，同功能重新注册只更新回调 |
| `Bindings.lua` | 共用文本写入、递归保护、颜色保留及分范围资料绑定 |
| `Modules/` | 地图标签、收藏、专业、声望、要塞、地下城排队、场景和成就条件 |
| 其他功能 Lua | 任务板、神器、物品与其他提示框、聊天链接、对白显示等原有功能 |
| `Changelog.lua`、`Welcome.lua` | 游戏内更新记录和介绍窗口 |
| `UI.lua` | 任务、书籍和读条入口，按相关事件安装功能，注册 `/lcn` 命令 |

移除混合多个界面职责的 `LocalClient.lua`，将其数据查找改名为 `FindCatalog`。这只是内部组织调整。`UI.lua` 在登录、相关暴雪界面加载或相关框体／全局处理函数出现与更换时补装挂钩；无关插件加载且目标未变化时跳过安装器。检查只读取已列明的目标引用，不扫描全部框体。

## 资源目录和加载清单

`scripts/resource-layout.mjs` 是目录、资源家族和加载顺序的唯一登记处，同时生成 TOC 与 `docs/resource-manifest.json`。

| `Data/` 子目录 | 内容 |
| --- | --- |
| `Shared` | 共享中文、基础中文串、名称串和分范围中文串 |
| `Quests` | 任务、原文保护索引、标题、目标、完成提示、补充对白和任务板 |
| `Dialogue`、`Books` | NPC 对话、书页及上下文 |
| `Items`、`Spells`、`Creatures` | 物品、法术、光环、NPC 及宠物名称 |
| `Maps` | 世界物件、地下城、地图地点和排队说明 |
| `Collections`、`Professions`、`Reputation`、`Garrison` | 收藏、专业、声望和要塞的分范围指纹 |
| `System`、`Artifacts` | 其他客户端说明、链接名称、系统固定文字和神器资料 |

加载顺序为：初始化 → 共享中文和其他资源 → 核心与共用工具 → 各功能模块 → 更新记录和介绍窗口 → 界面入口。仍按大小分片，默认每片赋值正文上限 900,000 字节，不合并成巨大单文件。单条赋值超过上限会使构建失败。

清单记录每片的家族、目录、大小和 SHA-256，以及运行时文件依赖。检查程序拒绝未知资源家族、错目录、重复条目、丢失文件、错误顺序、过期清单和悬空共享引用。新资源家族须先登记；不要手工调整 TOC 或生成资源。

## 共享中文

保留原有 `Strings`、`NameStrings`、指纹索引和数字 ID，仅将重复且能抵消声明／引用成本的中文常量放入临时 `SharedStrings` 池。资源加载时直接取得普通字符串；进入 `Core.lua` 后释放池表，运行中的匹配不经过额外共享表查找。

1.3.1 的构建结果为 22,185 段共享中文、131,372 处引用，生成的 Lua 文本减少 2,728,718 字节（约 2.6 MiB）。这是打包前资源文本的差额，不代表 ZIP 减少相同体积，也不是帧率或游戏内存实测。

## 构建与恢复

```powershell
npm ci --ignore-scripts
npm run build
npm test
npm run check
./scripts/package.ps1
```

构建默认从 `.cache` 读取已经下载并固定哈希的资料；也可以运行 `npm run build -- <资料目录>`。缺少资料或校验不通过时停止，不修改当前安装资源。

生成器的过程为：

1. 独占 `.cache/build.lock`，在同一仓库的 `.cache/build-stage-*` 中复制输入和运行时文件。
2. 生成资源、选择有收益的共享常量、按功能归档，生成 TOC、清单及审计报告。
3. 检查 Lua 5.1、中文资料、变量、共享引用、版本、更新记录、图标、资源哈希与加载顺序。
4. 再次核对配置、运行时代码、生成器和资料快照的输入哈希；期间有改动就拒绝替换。
5. 备份旧插件及被替换的 JSON 报告，再移动已校验的候选；出错时恢复旧文件。
6. 清理临时目录和构建锁。如果文件系统错误阻止回滚，保留临时目录中的备份并报告路径，仍释放锁。

该流程覆盖进程内可捕获的生成、校验与替换失败。突然断电或强制终止进程不保证自动回滚；遇到遗留锁时，应先确认没有构建进程，再检查临时目录和备份，不能直接清空整个 `.cache`。构建和打包均不自动安装到游戏目录，也不自动发布。

## 等价核对与测试边界

本次修改前保存了 1.3.0 的资源赋值基线，随后运行：

```powershell
npm run build -- --verify-equivalence docs/refactor-baseline-1.3.0.json
```

`resource-equivalence.mjs` 展开共享引用、对应内部目录改名，按资源表核对赋值数量和 SHA-256 汇总；目录、分片边界和相互独立的赋值顺序不作为差异。本次 40 组、2,273,007 条赋值一致，结果见 [refactor-equivalence.json](refactor-equivalence.json)，原始基线见 [refactor-baseline-1.3.0.json](refactor-baseline-1.3.0.json)。这用于验证本次资源搬迁，不应要求未来新增译文仍与旧版本相等。

测试另覆盖原版框体迟加载、无关插件事件、多个功能共用挂钩、异常后的递归保护、真实共享资源执行、构建锁和替换回滚。原有针对少量数据的测试通过 `tests/addon-fixture.mjs` 读取新目录并展开共享值；共享引用和生产加载顺序由独立集成测试验证。

自动检查不代替游戏中的排版、加载时间、内存、战斗保护与其他插件兼容性验收。1.3.1 的复测步骤见 [CLIENT-CHECK.md](CLIENT-CHECK.md)。
